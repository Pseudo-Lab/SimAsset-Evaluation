# 검사 결과를 서로 연결하기 위한 제출 초안

빗면·홈 검사 출력과 현재 입력기를 함께 확인하며 정리한 제안입니다. 세욱님·검사환경팀의 합의 전이며, 기존 공통 규약이나 DB 명세를 대체하지 않습니다.

## 기존 규약에서 확인한 사항

2026-11-18에 [검사환경 공통규약 v3](https://app.notion.com/p/v3-41ab17b7a07b8121a63ec99fd40b86be)의 본문과 댓글을 대조했습니다. 아래 내용은 새로 결정할 질문에서 제외합니다.

| 항목 | 확인한 내용 | 입력 연결에 적용할 점 |
| --- | --- | --- |
| 적용 불가 | 홈 검사에 `not_applicable`을 추가하자는 제안에 주영님의 수용 답변이 있습니다. | 누락·실행 오류와 구분합니다. 본문의 상태 목록에는 아직 없으므로 목록만 보고 거부하지 않습니다. |
| 조건별 폴더 | `{material}_{condition}_seed{n}` 형식을 모든 검사에 공통으로 쓰자는 답변이 있습니다. | 폴더 이름만으로 전역 실행 ID를 만들지 않습니다. 기존 빗면 형식도 보존하고 실제 식별 필드는 CSV·JSON과 대조합니다. |
| 홈 검사 도구 | 공에만 `condim=6`, 구름 마찰 `0.002`, `priority=2`를 적용하는 예외에 수용 답변이 있습니다. | 에셋 전체에 구름 마찰을 적용했다고 해석하지 않습니다. 공통 `solref`·`solimp`는 유지합니다. |

본문의 요약 CSV 11열, 공통 시계열 16열과 검사별 추가 시계열 형식은 현재 두 어댑터의 기준입니다. 본문에는 여전히 `[제안]`으로 표기되어 있어 팀 전체의 최종 출력 계약으로 확정하지 않습니다. 출력의 mm·s·도 단위, 반복 `N=10`·seed 0~9·기울기 ±2°·위치 ±1 mm도 같은 상태입니다. 이 기본안을 바탕으로 적용 범위와 예외만 확인합니다.

## 이번 결과에서 확인한 점

두 검사 모두 `summary.csv`에 실행 ID·에셋 ID·해시·검사·조건·seed·상태·측정값·단위를 기록합니다. `meta.json`에는 MuJoCo 버전과 timestep·조건이 있습니다. 실행을 반복해도 같은 원본 ID가 나올 수 있으며, 규약 버전·반복 번호·시작/종료 시각은 별도 합의가 필요합니다.

홈 검사의 `not_applicable`은 에셋 해시를 기록하기 전에 반환됩니다. 이 결과는 누락이나 실패로 세지 않습니다. 해시를 임의로 채우지 않으며, 같은 이름의 다른 에셋 버전과 자동으로 합치지 않습니다. 향후 공통 writer에서 입력 에셋 식별을 먼저 기록하는 방안을 제안합니다.

## 함께 정할 규칙

| 항목 | 제안 | 결정이 필요한 이유 |
| --- | --- | --- |
| 에셋 식별 | 선정 목록의 고정 ID와 원본 출처 ID를 분리하고, 가공본은 부모 버전과 연결합니다. | 표시 이름이나 폴더 이름만 같다고 같은 물체·버전으로 합치면 안 됩니다. |
| 내용 해시 | 원본 모델·참조 메시·적용 물성 중 어떤 파일을 포함하는지 명세합니다. | 현재 수신한 선언 해시만으로 원본 파일까지 검증됐다고 말할 수 없습니다. |
| 실행 ID | 실행할 때마다 고유 ID를 발급하고 seed·초기 자세·반복 번호를 별도 필드로 남깁니다. | 같은 조건의 반복과 같은 실행의 재전송을 구분해야 합니다. |
| 검사 버전 | 공통 규약 버전과 구현 commit을 각각 기록합니다. | 규약 변경과 코드 수정은 서로 다른 원인입니다. |
| 단위·좌표 | v3의 출력 mm·s·도 기본안을 기준으로, 각 검사 지표와 추가 시계열의 단위·좌표계를 확인합니다. | 이름에 `mm`가 있어도 값의 실제 단위를 추측하지 않으며 검사별 예외를 보존합니다. |
| 실행 시각 | UTC 시작·종료 시각을 기록하고 가져온 시각은 별도로 둡니다. | 파일 수정 시각이나 입력 시각을 실제 실험 시각으로 바꾸지 않습니다. |
| 수정·재등록 | 원본은 보존합니다. 재실행은 새 ID, 정정 산출물은 이전 ID와 수정 사유를 연결하는 방안을 제안합니다. | 현재 입력기는 같은 ID의 다른 내용에 `conflict`를 반환하며 덮어쓰지 않습니다. |
| 판정 | 자동 상태·자동 측정과 사람의 항목별 통과·실패·보류를 분리합니다. | `ok`나 `probe_pass=1`만으로 전체 품질 통과를 확정하지 않습니다. |

현재 어댑터는 위 새 필드를 임의 생성하지 않습니다. 미확인 값은 비워두고 원본과 경고를 보존합니다. 팀 공통 ID·정정 산출물 스키마가 정해지면 별도 대응을 추가합니다.

## 제출 전 누락 확인

실행 예정 목록은 **실험 전에** 만듭니다. 이미 존재하는 결과 폴더만 보고 예상 목록을 만들면 아예 생성되지 않은 실행을 찾지 못합니다. 선택한 50개 에셋에 어떤 검사·조건을 적용할지, v3의 seed 0~9 기본안을 모두 적용할지와 예외를 확인해야 전체 완료율을 계산할 수 있습니다. 같은 seed를 세 번 실행한 성능 비교는 서로 다른 seed 10개의 견고성 검사로 세지 않습니다.

현재 `audit`가 받는 최소 형식은 다음과 같습니다. `path`는 결과 배치의 상대 폴더이며, 예시는 홈 검사 한 건입니다.

```json
{
  "schema_version": 1,
  "runs": [
    {
      "path": "probe/mug_cad/file_decomposed_seed0",
      "asset_id": "mug_cad",
      "test": "probe",
      "condition": "decomposed",
      "seed": 0,
      "required_artifacts": ["clip_visual.mp4", "clip_collision.mp4"]
    }
  ]
}
```

```bash
uv run simasset-review audit /absolute/path/to/results \
  --expected /absolute/path/to/expected.json > audit.json
```

`expected_coverage_verified=true`는 이 예상 목록의 폴더·식별자·필수 파일이 모두 맞다는 뜻입니다. 예상 목록 자체가 팀의 50개 선정 결과를 충실히 반영하는지는 별도로 확인합니다. 검사 대상이 아닌 실행도 요약·사유를 제출하되 영상은 필수로 요구하지 않습니다.

현재 검사는 다음을 구분합니다.

- 실행 폴더 자체 없음, `summary.csv` 또는 `meta.json` 없음
- 예상 에셋·검사·조건·seed 불일치, 예상 목록 밖의 실행
- 같은 원본 ID의 중복·내용 충돌
- 잘못된 단위·시계열 정렬·필수 근거 파일 누락
- 홈 검사 적용 불가와 실제 실행 오류

반복마다 원본 ID가 같은 현행 출력은 반복별 namespace를 사용해야 합니다. 이 방법을 팀의 최종 ID 정책으로 확정한 것은 아닙니다.

## 먼저 받을 자료

1. 검사팀이 실제 실행한 각 검사 한 묶음: 정상, 적용 불가 또는 오류 사례, 영상이 있으면 함께 받습니다.
2. 선정 50개 ID와 결과 폴더 ID 대응표, 실행 예정 조합 목록을 받습니다.
3. 나머지 검사 출력의 공통 writer 버전과 단위 정의를 확인합니다.
4. 성준님과 항목별 판정 기준·필수 근거·보류 사유를 맞춥니다.

다시 결정할 필요가 없는 적용 불가 상태·폴더 형식·검사 도구 예외와, 아직 필요한 전역 ID·규약/코드 버전·재실행/정정 이력·판정 기준을 구분해 확인합니다.

모델 전체를 먼저 다시 내려받을 필요는 없습니다. 결과 파일만으로 입력 연결을 검토한 뒤, 모델 자체 검사가 필요할 때 해당 에셋과 이용 범위를 추가 확인합니다.
