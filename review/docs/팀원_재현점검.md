# 팀원 재현 점검과 짧은 시연

목표는 한 사람이 준비한 결과 묶음을 다른 사람이 받아 같은 실행·영상·측정값을 보고 판정을 남길 수 있는지 확인하는 것입니다. 아래는 준비된 절차이며, **다른 팀원의 실행 확인은 아직 받지 않았습니다.**

## 준비

[실행 안내](../README.md)에 따라 로컬 DB와 검토 화면을 시작합니다. 원본 하네스는 팀에서 공유한 것을 별도로 준비합니다. 이 저장소에는 원본 에셋이나 개인 인증 정보가 들어 있지 않습니다.

홈 검사 샘플은 원본을 수정하지 않는 래퍼로 재현할 수 있습니다. 기존 결과를 덮어쓰지 않도록 새 출력 경로를 사용합니다. 현재 영상 경로의 실측 환경은 macOS M1입니다. Linux headless 환경은 해당 렌더러를 별도로 설정·검증해야 합니다.

```bash
# review 폴더에서 실행합니다. --source는 압축을 푼 probe_env 폴더입니다.
uv run python scripts/probe_check.py \
  --source /absolute/path/to/probe_env \
  --output /absolute/path/to/new-probe-check --video

uv run simasset-review audit /absolute/path/to/new-probe-check/results \
  --expected /absolute/path/to/new-probe-check/expected.json

uv run simasset-review import /absolute/path/to/new-probe-check/results \
  --recursive --namespace my-probe-check-01 --origin local_reproduction
```

기본 실행은 컵·그릇·홈 없는 원기둥의 2가지 충돌 형상 조건, seed 0으로 총 6건입니다. `expected.json`의 이 6건은 래퍼가 실행하도록 정한 샘플 범위입니다. 팀의 50개 검사 계획이 아닙니다. `reproduction.json`에는 환경·원본 해시·실행 결과와 원본 변경 여부가 남습니다.

## 5분 시연 순서

| 순서 | 화면에서 할 일 | 확인할 결과 |
| --- | --- | --- |
| 1 | 검사 필터를 `probe`로 선택하고 `mug_cad / decomposed`를 엽니다. | 조건과 seed가 표시되며 시각 형상·충돌 형상 영상을 전환할 수 있습니다. |
| 2 | 공의 진입 깊이와 원본/SI 측정값을 봅니다. | 공을 놓기 전 빈 값은 0으로 그려지지 않습니다. `probe_pass`는 측정값으로만 보입니다. |
| 3 | `solid_cyl`을 엽니다. | 검사 대상 아님과 해시 미기록을 확인합니다. 누락·실패로 합치지 않습니다. |
| 4 | 같은 import 명령을 한 번 더 실행합니다. | 6건 모두 `duplicate`이며 실행 수가 늘어나지 않습니다. |
| 5 | 검토 항목과 근거를 선택하고 `보류` 시험 판정을 저장합니다. | 평가자는 `재현 확인 - 본인 이름`, 기준은 `review-smoke-1`로 두어 팀의 실제 품질 판정과 구분합니다. |
| 6 | 이유를 고쳐 저장한 뒤 페이지를 새로고침합니다. | 현재 판정과 이전 판정이 함께 남습니다. |

팀의 실제 품질 판정은 합의된 기준으로 별도 수행합니다. 시험 판정 때문에 에셋을 통과 처리하지 않습니다.

## 남길 확인 결과

- 실행한 코드 commit과 OS·Python·MuJoCo 버전
- `audit`의 예상/유효/누락 개수와 import/reimport 결과
- 영상 두 종류의 재생 여부, 깊이 그래프의 관측 개수
- 판정 저장·수정·새로고침 후 이력 유지 여부
- 막힌 명령이나 혼동된 화면과 오류 문구

전체 원본이나 인증 파일을 보낼 필요는 없습니다. 검사 결과 JSON과 문제 화면으로 먼저 확인할 수 있습니다. 현재 로컬 URL은 다른 사람의 컴퓨터에서 접속할 수 없으므로, 코드·자료를 공유하거나 함께 화면을 보며 점검해야 합니다.
