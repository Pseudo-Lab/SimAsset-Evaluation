# 결과 검토 · Grafana 화면 개편

2026년 11월 18일 기준입니다. 이미지 생성으로 만든 시안을 참고해 결과 검토 웹앱과 Grafana의 정보 순서, 색상, 상태 표현을 맞췄습니다. 기존 원문과 판정 저장 구조는 유지합니다.

## 화면에서 달라진 점

| 화면 | 변경 내용 |
| --- | --- |
| 공통 | 짙은 회색 표면, 민트색 강조, 일관된 테두리·여백·글자 위계를 사용합니다. 자동 실행 상태와 사람 판정을 다른 이름으로 표시합니다. |

| Grafana | 저장된 실행·에셋 이름·실행 오류·판정된 실행을 먼저 보여주고, 상태 분포 → 최근 판정 → 에셋별 표 순으로 구성합니다. 긴 측정값 표는 필요할 때 펼칩니다. 실행 링크는 해당 영상·판정 화면으로 연결됩니다. |

## 데이터 표시 원칙

- 시안의 인명·예시 수치·영상은 구현 데이터에 사용하지 않습니다. 웹앱은 기존 API와 원본 영상만 표시합니다.
- `실행 완료`는 하네스 실행 상태입니다. 사람의 `통과 / 불통과 / 보류`와 구분합니다. `probe_pass`도 사람 판정으로 전환하지 않습니다.
- `대상 아님`은 오류나 불통과로 표시하지 않습니다. 미측정은 0으로 채우지 않습니다.
- 그래프는 빈 관측 구간을 선으로 이어 붙이지 않습니다. 키보드 방향키 또는 포인터로 관측값을 확인할 수 있습니다.
- 핵심 깊이 값은 SI 저장값을 mm로 환산합니다. 전체 측정값 탭에는 SI 값과 원본 값·단위를 함께 보존합니다.
- Grafana의 에셋 수는 **에셋 이름 종류 수**입니다. 여러 버전이나 실행을 50개 실물 에셋 평가 완료율로 해석하지 않습니다.
- Grafana는 기존 조회 전용 DB 계정과 기본 패널만 사용합니다. 외부 플러그인·공유 DB·GPU 자원은 추가하지 않습니다.

## 라이트 · 다크 테마 추가

검토 화면에 라이트·다크·시스템 선택기를 추가했습니다. 선택을 첫 화면 표시 전에 적용하고 브라우저에 저장합니다. 그래프·배지·입력창·표의 색상과 로고도 함께 바뀝니다. 390px 폭에서는 탐색 링크를 다음 줄로 배치해 테마 선택기가 잘리지 않습니다.

Grafana는 고정된 밝은 색상 대신 테마에 대응하는 기본 색상 이름을 사용합니다. **테마 설정** 링크와 기본 **Change theme** 메뉴를 사용합니다. URL만 바꾸는 같은 화면 내 이동은 테마가 즉시 반영되지 않아 빠른 전환 링크로 채택하지 않았습니다.

- 검토 화면의 라이트·다크 전환, 새로고침 후 선택 유지, 시스템 모드 선택을 확인했습니다. 전환 중 검색값과 선택한 실행이 유지됐습니다.
- Grafana의 기본 메뉴에서 테마 선택과 사용자 설정 저장을 확인했습니다.
- 390px 폭에서 페이지 너비는 375px이었고, 테마 선택기가 화면 안에 표시됐습니다. 임시 화면 크기 설정을 복원했습니다.
- 표시 규칙 검사 4개와 JavaScript 구문 검사를 통과했습니다. Grafana SQL은 이전 버전과 동일합니다.

## 한국어·영어 화면과 다국어 판정

결과 검토 화면에 **한국어 / English** 선택을 추가했습니다. 메뉴·판정 버튼·입력 안내·알림·날짜·접근성 레이블을 전환하며, 입력창을 다시 만들지 않아 작성 중인 판정과 근거 선택이 유지됩니다. 선택은 브라우저에 저장되고 `?lang=en` 또는 `?lang=ko`로도 지정할 수 있습니다. 기존 라이트·다크·시스템 선택과 함께 사용할 수 있습니다.

Grafana는 동일한 한국어 구성을 바탕으로 영문 대시보드를 생성합니다. 상단에서 언어를 바꾸고 해당 언어의 결과 검토 화면으로 이동할 수 있습니다. SQL·조회 계정·수치·원본 식별자는 두 화면에서 동일합니다. Grafana 자체 메뉴의 언어는 Grafana 사용자 환경설정을 따릅니다.

판정 원문, 평가자, 파일명, 원본 측정 항목은 화면 언어에 맞춰 임의로 번역하지 않습니다. 자동 실행과 사람 판정의 구분도 그대로 유지합니다. 통과·불통과·보류의 저장 코드는 `pass / fail / inconclusive`로 고정하여 언어별 집계가 갈라지지 않게 합니다.

### 발견한 문제와 보완

| 항목 | 확인과 변경 |
| --- | --- |
| 글자 수 계산 | 기존 HTML `maxlength`는 UTF-16 단위, 서버는 Unicode 코드 포인트 단위여서 이모지의 허용 길이가 달라질 수 있었습니다. 입력 카운터·검증을 서버와 같은 코드 포인트 기준으로 맞췄습니다. |
| 한글 등 조합 입력 | 조합 중에는 검증을 보류하고 조합 완료 후 확인합니다. 입력을 잘라내거나 임의로 문자 정규화하지 않습니다. |
| 잘못된 문자 | PostgreSQL에 저장할 수 없는 NUL과 단독 surrogate를 저장 전에 422 오류로 처리합니다. 오류 응답에 판정 원문 전체를 되돌려 보내지 않습니다. |
| RTL 문장 | 판정 이유·평가자·기준에 글 방향 자동 판정과 분리 표시를 적용했습니다. 아랍어·히브리어와 영어·한국어가 섞여도 화면 레이블에 글 방향이 번지지 않게 했습니다. |
| 검색 | 한국어·영문 검사 이름과 조건을 모두 찾습니다. 검색할 때만 NFC를 적용하므로 한글 조합 형태가 달라도 일치하며 저장 원문은 유지합니다. |
| 좁은 화면 | 영문 선택기·버튼과 핵심 측정값을 확인했습니다. 긴 소수가 숫자 중간에서 줄바꿈되는 문제를 보완했습니다. |

`maxlength`의 기준은 [MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/maxlength), 저장 인코딩은 [PostgreSQL UTF-8 안내](https://www.postgresql.org/docs/16/multibyte.html)를 참고했습니다. 실제 시험 DB의 `server_encoding= UTF8`도 확인했습니다.

브라우저 저장 시험은 별도 DB에서 진행했고 시험 서버·탭·DB를 정리했습니다. 실제 검토 DB는 **27개 실행 / 7개 에셋 이름 / 판정이 있는 실행 1개**로 유지했습니다. 검증한 API 수정본도 로컬 서버에 적용했습니다.

모든 언어·운영체제의 글꼴과 실제 IME 조합 입력을 전수 검증한 것은 아닙니다. 화면 번역은 한국어와 영어를 지원하며, 다른 언어의 판정 원문은 보존합니다. 결합 문자·이모지의 길이는 눈에 보이는 글자 묶음 수와 다를 수 있고, 기존과 같이 앞뒤 공백은 저장 시 제거합니다.
