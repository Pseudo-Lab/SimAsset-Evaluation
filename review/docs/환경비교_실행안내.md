# CPU 물리와 렌더링 비교

물리 계산의 차이, 같은 상태를 그리는 차이, 영상·파일을 포함한 전체 처리시간을 나누어 측정합니다. Azure 개인 실험은 팀의 공통 실행환경 결정과 별개입니다.

## 로컬 기준

공유 하네스를 별도 폴더에 풀고 `--source`에 지정합니다. 원본 코드를 수정하지 않습니다. 새 출력 폴더만 사용하며 기존 폴더 덮어쓰기는 거절합니다.

```bash
uv run python scripts/benchmark.py source \
  --source /absolute/path/to/incline_env \
  --assets block_mu03 tall_box blob_mesh --repeats 3 \
  --output .state/benchmarks/cpu-harness

uv run python scripts/benchmark.py physics \
  --source /absolute/path/to/incline_env --asset block_mu03 \
  --output .state/benchmarks/block_mu03-cpu

uv run python scripts/benchmark.py render \
  --states .state/benchmarks/block_mu03-cpu \
  --output .state/benchmarks/block_mu03-render

uv run python scripts/benchmark.py source \
  --source /absolute/path/to/incline_env --assets block_mu03 tall_box blob_mesh \
  --repeats 3 --video --profile --output .state/benchmarks/full-profiled
```

`source`는 원래 하네스의 조기 종료 조건을 유지합니다. `physics`는 같은 초기 상태로 8초·4,000 step을 강제 실행하므로 두 시간은 서로 다른 측정입니다. `render`는 저장한 240개 상태를 복원하고 `mj_forward`와 렌더링만 수행합니다. `mj_step`을 다시 호출하지 않습니다.

`--profile`은 원본 함수의 경계에서 모델 구성, CPU step, 영상 캡처·렌더·인코더 전달, 영상 종료, plot을 측정합니다. 계측 자체의 오버헤드가 있습니다. ffmpeg는 별도 프로세스이므로 전달·종료 대기를 순수 인코딩 시간이라고 해석하지 않습니다. E2의 한 시점 영상과 E3의 visual/collision 2종 영상도 출력 범위가 다릅니다.

## Linux GPU에서 실행할 묶음

지원 NVIDIA 드라이버·OSMesa·ffmpeg·uv가 있는 개인 전용 VM을 먼저 준비합니다. 드라이버 설치와 재시작은 실행 중인 실험과 분리합니다. `nvidia-smi`와 실제 OpenGL 렌더러를 둘 다 확인합니다. [Azure 드라이버 안내](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/n-series-driver-setup)는 NCasT4_v3의 지원 CUDA/GRID 경로를 구분합니다. 설치 시점에 GPU·OS에 맞는 공식 드라이버와 이용 조건을 확인합니다.

```bash
# Ubuntu 환경에서 필요한 일반 패키지 예시입니다. GPU 드라이버는 별도입니다.
sudo apt-get update
sudo apt-get install -y libosmesa6 libegl1 libgl1 ffmpeg
uv sync --locked --extra benchmark

uv run python scripts/cloud_benchmark.py \
  --source /absolute/path/to/incline_env \
  --baseline /absolute/path/to/local-baseline \
  --output /absolute/path/to/new-cloud-results --max-minutes 30
```

baseline 폴더에는 `block_mu03-cpu`, `tall_box-cpu`, `blob_mesh-cpu`의 `physics` 결과를 둡니다. 각 폴더의 원본 코드·에셋 해시, MuJoCo 버전과 조건을 대조합니다. 다른 초기 상태나 파일 변조가 있으면 비교를 거절합니다. 플랫폼 간 MJB 호환성에 의존하지 않고 E1에서 해당 호스트의 모델을 다시 만들며, E2-SW/GPU 두 경로는 같은 E1 모델·상태를 사용합니다.

실행 순서는 E1 CPU → E2 OSMesa llvmpipe → E2 EGL NVIDIA → E3 전체 SW/GPU입니다. 각 3회 반복하며, GPU 이름·드라이버와 1초 간격 사용률·VRAM 샘플을 남깁니다. 1초보다 짧은 순간의 메모리 최대값을 보장하는 측정은 아닙니다. 예상한 렌더러가 아니면 실패로 멈춥니다.

수치 비교 초안은 위치 성분 `1e-6 m`, quaternion 성분 `1e-6`입니다. 동일 조건의 차이를 찾는 진단값이며 팀의 통과 기준이 아닙니다. 그림 두 장의 RGB 오차는 시각적 차이만 설명합니다. 전체 영상 확인과 사람 판정은 별도입니다.

## 구독·시간·종료 보호

`azure-lab.example.json`을 `.state/azure-lab.json`으로 복사하고 실제 구독·테넌트를 넣습니다. 모든 CLI 호출은 이 구독을 명시합니다. 전역 기본 구독을 바꾸지 않습니다. 사전 확인은 읽기 전용입니다.

```bash
uv run python scripts/azure_guard.py preflight \
  --config .state/azure-lab.json --evidence .state/azure-preflight-NEW.json
```

유료 실행 전에 사용자의 지출 한도·최대 시간·해당 승인 기록과 단가·비컴퓨트 예상비용을 설정해야 합니다. 예시 계획이나 계산표의 숫자는 승인이 아닙니다. VM은 `rg-simasset-personal-gpu-lab` 안에 만들고 `purpose=simasset-personal-gpu-lab` 태그를 사용합니다. 이 도구는 VM을 만들거나 시작하지 않습니다. 생성 시에도 같은 구독과 예상 VM 크기를 명시하고, 생성된 실제 ID를 확인합니다.

```bash
# 이미 승인·생성·준비된 개인 VM에서만 실행합니다.
# SSH 호스트 키를 정상 확인한 연결과 결과 회수 명령을 한 스크립트로 묶습니다.
uv run python scripts/azure_guard.py run \
  --config .state/azure-lab.json --evidence .state/azure-run-NEW.json \
  --command /absolute/path/to/run-and-retrieve-results.sh
```

guard는 실제 VM의 구독·그룹·이름·태그·지역·크기를 검사하고, 관리 영역의 자동 종료 시각을 설정한 뒤 제한 시간 동안 명령을 실행합니다. 성공·실패·시간 초과 후 `deallocate`를 호출하고 `PowerState/deallocated`를 확인합니다. 관리 영역 자동 종료는 로컬 연결이 끊길 경우를 위한 보조 장치이며, 정확한 금액의 결제 차단은 아닙니다. [자동 종료](https://learn.microsoft.com/en-us/azure/virtual-machines/auto-shutdown-vm)와 [VM 상태별 청구](https://learn.microsoft.com/en-us/azure/virtual-machines/states-billing)를 구분합니다.

결과 회수·해시 확인 후 잔여 디스크·IP·스토리지의 유지 여부를 결정합니다. guard는 잔여 목록을 기록하며 자동 삭제하지 않습니다. 실제 청구는 Cost Management 반영 후 따로 확인합니다. 개인 실험 자원이 아닌 VM은 종료하지 않습니다.

## 아직 실행하지 않은 범위

Azure GPU 할당량 요청은 `Unauthorized`로 거절됐습니다. 유료 VM은 생성하지 않았습니다. cloud runner와 종료 보호는 로컬 검사·실패 경로 시험을 수행했지만 실제 Azure 실행·자동 종료·할당 해제의 종단 검증은 남아 있습니다. 팀 전체 에셋·6개 검사의 처리량, GPU 속도 향상, 실제 청구액과 MJX 물리 계산은 확인하지 않았습니다.
